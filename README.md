# VoiceBento

소리와 영상을 올리면 전사문으로 바꿔 두고, 눌러 들으며 고쳐 읽는 자리.
`MailBento` · `MemoBento` · `PaperBento` 와 한 스택에서 도는 다섯째 앱이다.

- 소리든 영상이든 올리면 된다. 영상이면 오디오 트랙만 뽑아 쓴다.
- 전사는 **sherpa-onnx + NVIDIA parakeet-tdt-0.6b-v3 (int8)** 이 한다. CPU 만 쓴다.
- 전사문은 BentoAgent 가 한 번 더 다듬는다. **문장만 다듬는다** — 화자는
  안 건드린다.
- **화자는 소리로 가른다.** 말한 사람 목록을 적어 주면 목소리를 재서 무리를
  짓고, 그 무리에 이름을 단다. 한 줄 안에서 화자가 바뀌는 자리까지 나눈다.
- 타임스탬프를 누르면 그 시각으로 재생이 뛴다. 전사문은 손으로 고칠 수 있고,
  고친 줄은 다시 다듬어도 덮이지 않는다.

## ⚠️ 한국어는 못 알아듣습니다

이 앱이 쓰는 전사 모델(`parakeet-tdt-0.6b-v3`)의 어휘 8,193개에는 **한글이
하나도 없습니다.** 한국어 소리를 넣으면 오류가 나지 않고 **빈 글이나 엉뚱한
로마자**가 나옵니다. 영어를 비롯한 유럽 25개 언어용입니다.

알고 고른 선택입니다. 앱은 결과가 그 모양일 때 화면에 그 사실을 알려 줍니다.

이 문장들은 **손으로 적힌 것이 아니라 모델 서술자에서 만들어집니다**
(`scripts/asr-models.json`). 한국어를 하는 모델로 갈아 끼우면 화면의 안내도
함께 바뀝니다 — 아래 "모델 갈아 끼우기" 를 보세요.

## 세션 — 한 전사문은 한 세션에서 처리된다

녹음 하나가 곧 세션이던 시절이 있었다. 그래서 방금 다듬으며 정한 화자 이름을
대화창이 몰랐고(다듬기가 일회용 세션이었다), 지난주 회의에서 쓴 용어를 이번 주
회의가 물려받을 길이 없었다.

지금은 **세션이 따로 있다.** 이름을 갖고, 녹음이 여럿 붙고, 그 녹음들의
다듬기와 대화가 같은 에이전트 세션에서 돈다.

- 올릴 때 고른다 — 기존 세션에 이어 붙이거나, 새 세션을 만들거나, 세션 없이.
- 세션이 없는 녹음도 그대로 된다. 그때는 예전처럼 녹음 하나가 곧 세션이다
  (세션이 생기기 전에 올린 녹음이 전부 이 상태다).
- **세션을 지워도 전사문은 남는다.** 사라지는 것은 이름과 그동안 오간 대화뿐이고,
  녹음은 "세션 없음" 으로 간다.
- **같은 세션의 다듬기는 하나씩 돈다.** 세션 하나가 저쪽에서 claude 세션
  하나라, `--resume` 이 겹치면 맥락이 꼬인다. 회의 녹음 셋을 한 세션에 나란히
  올리면 전사가 끝나는 대로 다듬기가 저절로 시작되므로 실제로 겹친다.
- **맥락에는 상한이 있다** (`SESSION_CONTEXT_CHARS`, 기본 60만 자). 넘으면
  조용히 자르지 않고 409 로 거절하고, 사람은 새 세션으로 옮기거나 그 세션의
  에이전트 맥락만 새로 시작한다(`POST /api/sessions/<id>/rollover` — 이름과
  녹음과 전사문은 그대로, 오간 대화만 사라진다).

**도구는 여전히 안 준다.** 세션이 오래 살수록 그 규율이 더 중요해진다 —
여기 실려 가는 것은 남이 만든 소리에서 받아 적은 글이고, 세션이 길어질수록
그런 글이 쌓인다. 늘린 것은 맥락이지 권한이 아니다.

## 모델 갈아 끼우기

모델의 성질은 **한 곳에만 적혀 있다** — `scripts/asr-models.json`.
파일 이름도, 지원 언어도, VAD 상한도, 스레드 수도, 시각 능력도, 출처
고지도 거기서 온다. 워커·화면·에이전트 프롬프트가 전부 거기서 읽는다.

모델을 하나 더 붙이려면:

1. `scripts/asr-models.json` 에 서술자 한 칸.
2. 파일 구성이 다르면 `scripts/transcribe.mjs` 의 `RECOGNIZERS` 에
   **결과 모양 어댑터** 하나 (transducer 와 whisper 는 이미 있다).
3. `ASR_MODEL_ID` 로 고른다.

서술자에는 불변식이 걸려 있고 어긋나면 **앱이 뜨지 않는다** — 이를테면
VAD 조각 상한이 모델 상한보다 작아야 한다 (parakeet 은 401초에서 죽는다).
전사가 조용히 틀린 글을 내는 것보다 안 뜨는 편이 낫다.

`timestamps` 가 `"none"` 인 모델(sherpa-onnx 의 whisper가 그렇다 — 낱말 시각을
아예 안 준다)이 오면 낱말 클릭이 접히고 줄 클릭만 남는다. 그 갈래는 코드에
실제로 있다.

## 어떻게 도는가

```
브라우저 ──8MB 조각──▶ VoiceBento ──그대로──▶ MemoBento (파일이 사는 곳)
                          │
                          │ 전사 줄 세우기 (기본 동시 1건)
                          ▼
                    자식 프로세스: scripts/transcribe.mjs
                      (모델의 성질은 --spec 으로 받는다)
                      ffmpeg → 16kHz 모노 WAV
                      silero VAD (조각 최대 30초 — 서술자가 정한다)
                      조각마다 디코딩 (numThreads 4 — 서술자가 정한다)
                          │ 조각 하나 끝날 때마다 stdout JSON 한 줄
                          ▼
                        SQLite (segments)
                          │
                          ▼
                    BentoAgent /voice/polish  ← 다듬기 · 화자 추정
```

**파일은 이 앱에 없다.** 올라온 조각은 MemoBento 의 예약 메모함으로 그대로
흘러가고, 이 앱은 `fileId` 만 들고 있다. 재생도 그쪽 파일 라우트로 프록시한다
(Range 를 그대로 넘겨서 `<audio>` 의 탐색이 그대로 된다).

**전사는 반드시 자식 프로세스에서 돈다.** `sherpa-onnx-node` 의 C++ 예외는
N-API 를 넘으며 `std::terminate()` 를 부른다 — `try/catch` 로도
`uncaughtException` 으로도 안 잡히고 프로세스가 SIGABRT 로 죽는다. Next 서버
안에서 돌리면 긴 파일 하나가 앱 전체를 죽인다.

## 띄우기

```bash
npm install          # 앱
npm run asr:install  # 전사 워커의 네이티브 의존성 (플랫폼별 수백 MB)
npm run model:fetch  # 모델 671MB 를 MODEL_DIR 에 (있으면 건너뜀)
cp .env.example .env.local   # 값을 채운다 (MEMOBENTO_URL 은 필수)
npm run dev
```

ffmpeg 이 `PATH` 에 있어야 한다 (도커 이미지에는 정적 바이너리가 들어 있다).

도커로 띄우면 진입점이 모델을 알아서 챙긴다. 모델은 **이미지에 굽지 않고
볼륨에 둔다** — 구우면 런타임 이미지가 1.7GB 가 된다.

### bento 스택에 얹을 때

혼자 돌 때와 환경변수가 다르다. 스택은 모델을 호스트에서 미리 받아
**읽기 전용**으로 물리고, 앱은 아무것도 내려받지 않는다.

| 값 | 뜻 |
| --- | --- |
| `ASR_MODEL_DIR` | 모델 폴더. 있으면 `MODEL_DIR` 을 이기고, 내려받지 않는다 |
| `VAD_MODEL_PATH` | silero VAD 파일. 스택에서는 모델 폴더 **밖**에 있다 |
| `MEMOBENTO_API_URL` | **서버가** 파일을 주고받을 주소 (`http://memobento:3000`) |
| `MEMOBENTO_URL` | **사람이 누르는** 버튼의 바깥 주소 (`https://…/memo`) |
| `ASR_THREADS` | `ASR_NUM_THREADS` 의 다른 이름. 설치 마법사가 적는 쪽 |
| `ASR_MODEL_ID` | 어느 서술자를 쓸지. 비우면 기본값. 모르는 id 면 앱이 안 뜬다 |
| `SESSION_CONTEXT_CHARS` | 세션 하나가 에이전트 맥락에 부을 수 있는 글자 수 |

`MEMOBENTO_URL` 과 `MEMOBENTO_API_URL` 을 **하나로 합치지 마라.** 바깥 주소로
파일을 나르면 요청이 터널을 한 바퀴 돌아 나갔다 들어오면서 Cloudflare 무료
플랜의 업로드 100MB 한계와 Access 로그인 화면을 만난다. 한 시간짜리 녹음은
대개 그 한계를 넘는다.

컨테이너는 **안에서 3000 번을 듣는다** (형제 앱들과 같다). 호스트 3003 은
compose 가 잇는다: `"${VOICEBENTO_PORT:-3003}:3000"`.

## 화자 나누기

전사가 끝나면 **소리를 들어** 누가 말했는지 가른다. 화면 위쪽 "화자" 에서
말한 사람 목록을 적고 누르면 된다. 옛 녹음도 같은 단추로 다시 나눌 수 있고,
**전사문은 한 글자도 안 바뀐다.**

- **목록은 넉넉히 적는 편이 낫다.** 한 사람을 빠뜨리면 정확도가 8.3pt
  떨어지고, 한 사람을 더 적으면 4.1pt 오른다 (AMI 9편 실측). 목록에 없던
  사람은 `other` 로 묶인다.
- **한 줄 안에서도 화자가 바뀐다.** VAD 조각의 절반 남짓에 화자가 둘 이상이다.
  줄 통째로 한 사람을 붙이면 낱말 정확도가 61.9% 인데 줄 안을 나누면 73.5% 다.
- **이름은 목소리마다 고친다.** 한 칸을 고치면 그 목소리의 모든 줄이 함께
  바뀐다. 한 줄만 잘못 붙었으면 그 줄에서 고치고, 그렇게 고친 줄은 다시
  나눠도 안 덮인다.
- **"덜 확실하다" 까지만 말한다.** 줄에 붙는 표시는 "틀렸다" 가 아니다 —
  멀쩡한 줄에도 붙고, 잘못 붙은 줄에는 대개 안 붙는다.
- 세 시간이 넘는 녹음은 안 나눈다 (메모리). 그때도 전사문은 그대로 나온다.
